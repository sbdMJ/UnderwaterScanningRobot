# Diff-WMPC의 수중 도메인 적용: 원논문 대비 변경점과 남은 concern

작성 2026-08-10. 원논문(Jahncke et al., RA-L 2026)과의 **환경** 차이는
`docs/research/domain_comparison.md`, 변경 과정의 실험적 근거(시도·기각·채택)는
`docs/experiments/tuning_history/diff_tuning_history.md` (V1–V8a 여정)에 있다.
이 문서는 "방법이 어떻게 달라졌고, 왜 그래야 했으며, 무엇을 더 걱정해야 하는가"를
논문 방법론·리뷰 대응 관점으로 정리한다.

## 1. 원논문에서 유지한 것 (방법의 정체성)

| 요소 | 상태 |
|---|---|
| solver-in-the-loop 그래디언트 (acados forward sensitivity → 정책 역전파) | 유지 — 동일 스택 (SQP_RTI/HPIPM, 감도는 EXACT Hessian) |
| 경량 FC 정책 (2×128) → 대각 비용 가중치 | 유지 |
| Adam + grad clip ±0.1 + batch 10 timestep 미니배치 | 유지 |
| "학습은 짧고 샘플 효율적" 주장 | 유지·강화 — 최종 레시피 60k 스텝(≈50분), RL(1M)과의 격차 구도 동일 |
| bounded 가중치 출력 (양수·유계) | 유지 (softplus 대신 log-scale sigmoid — §2.2) |

## 2. 변경점 (도메인 요구에 의한 것)

### 2.1 정책 입력: 미래 참조 → 현재 오차 + phase (+히스토리)

원논문의 핵심 메커니즘은 look-ahead(향후 2.55 s의 속도·곡률 10차원)로 코너를
**선제** 대비하는 것이고, ablation(Fig.8)으로 그 필요성을 입증했다. 우리는 V1으로
동일 메커니즘(horizon setpoint 델타)을 이식해 **통제 실험으로 검증했으나 기각**했다
(실패 축 개선 없음, 일부 악화). 원인: 스캔 참조는 상태머신이 만드는 조각별 선형
램프라 위상(phase sin/cos) + 오차 히스토리가 이미 충분통계에 가깝고, 레이싱 곡률
같은 예측 불가한 미래 정보가 없다. **주의**: 코드에는 `preview_nodes` 경로가 남아
있고 ckpt가 스펙을 자기서술하므로, 참조가 복잡해지는 미래 태스크에서 재활성 가능.

### 2.2 가중치 공간: 6 → 18, log-scale, per-entry 하한

- 6-DOF·6추력기라 오차 12축 + 제어 6축. 탐색 범위 0.1–5,000은 수동 스윕 실측
  (w_roll≈2,000에서만 sway 기생 모멘트 상쇄)으로 정당화 — 원논문 orbit 포팅의
  상한 500은 이 도메인에서 최적해를 배제한다.
- log-scale sigmoid: 4자릿수 범위에서 학습 신호 균형.
- **per-entry 하한** (radial/heading=10): 2026-07-31의 w_radial 붕괴 실측 이후의
  보험이자, dr75/s2 충돌에서 최악을 막은 실제 안전망. 원논문에 없는 장치.

### 2.3 손실·그래디언트: 다중 노드 합 + 정규화 제어항 + 포화 스킵

- **다중 감도 노드 {N/6, N/3, 2N/3, N}** (원논문: 노드 1): 단일 원거리 노드는 빠른
  축(자세, ~0.1 s)만 최적화하고 느린 축(반경 드리프트)을 버리는 실측 병리 →
  노드 합으로 시간스케일 재균형. 원논문의 "노드 1이 최선" 결론은 그들의 상태
  차원·시간상수에선 맞지만 우리에겐 반대.
- **정규화 제어항** u/max_thrust: 뉴턴 단위 효과항은 추종항을 압도해
  "learn-to-do-nothing" 병리 (참조 구현 경고 계승).
- **포화 스텝 스킵**: 감도가 제약 경계에서 정확히 0 (FD 대조 실측) — 0-그래디언트는
  노이즈가 아니라 조용한 오류. E4a에서 스킵 제거가 공칭 평가상 무차별로 나왔지만,
  이는 "비용이 없다"는 뜻이지 "불필요하다"가 아님 — 학습 안정성 이력 쪽 주장으로 보고.

### 2.4 학습 데이터 구성: 랩 연속 주행 → 랜덤 세그먼트 + 자세 커버리지

- 랩(≈27 s) 단위 학습이 가능한 레이싱과 달리 우리 에피소드는 180 s × 4 phase —
  같은 스텝 예산으로 상황 다양성을 사려면 **600-스텝 랜덤 세그먼트**(반경·방위·
  심도·자세·phase 추첨)가 필수.
- **캠페인의 결정적 발견**: 배포 분포의 초기자세 스트레스(±45°)가 학습 분포(±5°)
  밖이라 OOD에서 정책이 가중치를 바닥에 고정 → 충돌. 해법은 동역학 DR(기각)이
  아니라 **자세 커버리지** — 최종 레시피 `attitude_range 0.7 rad, extreme 20% 혼합,
  60k 스텝` (50% 혼합은 공칭 정밀도를 잠식; 20%가 실측 스윗스팟).
- 원논문의 모델-불일치 학습(내부 Sim1/구동 Sim2)과 달리 **동역학 DR 혼입은 우리
  도메인에서 해로움** (V5: 실패 축 그대로 + 전반 희석) — 플랜트-지배가 아닌
  도메인에서는 플랜트 다양화가 학습 신호만 흐린다는 대조적 교훈.

### 2.5 체크포인트 자기서술 (엔지니어링 변경)

hidden/history/preview 스펙과 bounds가 ctor 인자에만 있으면 로드 시 조용한 의미
변화 사고가 난다 (실제로 구형 ckpt가 로드 불가 상태로 방치돼 E1이 4/5 방법에
머물렀던 원인). bounds·preview를 버퍼로 동봉하고 `WeightPolicy.from_state_dict`가
ckpt에서 아키텍처를 역추론하도록 변경 — 원논문 코드에 없는 재현성 장치.

### 2.6 lr: 5e-4 유지 (원논문 2.9e-5)

원논문은 BO로 lr을 선정(보수적 2.9e-5). 우리는 5e-4에서 V8a가 수렴·채택됐고
계획했던 보수-lr 대조(V3)는 자세 축이 지배 요인으로 판명되며 우선순위에서 밀림.
**미완 항목**으로 기록 (concern C-8).

## 3. 결과 구도의 반전 (해석 변경)

| | 원논문 | 본 연구 |
|---|---|---|
| zero-shot 전이 | 열화 존재 → 27 s fine-tune으로 회복 | 고정 플랜트 3종에서 **zero-shot ≈ ft ≈ from-scratch** |
| 가변 가중치의 가치 축 | 플랜트 한계 선제 대비 (look-ahead) | **상황 전환 대응** (phase·자세; E4a preview +41%, F7 tilt) |

논문 서술: "저속 준정적 도메인에서는 플랜트 적응이 아니라 상황 적응이 가변
가중치의 가치이며, zero-shot이 environment-specific 상한에 이미 도달한다" — 이는
방법의 실패가 아니라 도메인 특성의 발견으로 프레이밍한다 (from-scratch 기준선이
방어 근거).

## 4. 남은 concern (다음 단계 논의용)

- **C-1 (안전 구조)**: 벽 회피가 OCP 하드 제약이 아니라 비용+가중치 정책에
  의존한다. dr75/s2 충돌이 보여준 것: 정책이 무너지면 안전도 무너진다. per-entry
  하한이 사실상의 안전망인데, 이는 원논문도 future work로 남긴 "formal safety
  guarantee" 부재의 우리 버전. → 옵션: wall-clearance 하드 제약을 OCP에 추가하거나
  가중치 하한을 안전 인증 관점에서 정당화.
- **C-2 (상태추정 하의 미검증)**: 전 결과가 GT 상태 기준. sim-to-real 축이 EKF
  조건에서 ssi/nominal의 5–7× 열화를 실측·수정했지만 **diff는 EKF 조건 미평가**.
  가중치 정책 입력이 추정 오차로 오염될 때의 거동(특히 OOD-유사 반응) 확인 필요 —
  E5 전 필수 게이트로 제안.
- **C-3 (E2 스윕 축)**: 유체계수 축은 평탄 (부호 상쇄 + 자세 지배). 단조 강건성
  곡선이 논문에 필요하면 초기자세 스윕 조건 신설이 정공법 (additive,
  sim-to-real과 무충돌 — figure_trend_audit §4).
- **C-4 (통계력)**: E2/E3 시드 3개, E2b′ 플랜트 3종 — 결론(동률)의 신뢰구간이
  넓다. 채택 주장에는 충분하나 "우위" 주장에는 시드 확대 검토.
- **C-5 (실시간 예산)**: solve 8–9 ms(데스크톱) vs 제어 주기 20 ms — Jetson
  실측(E4c) 전까지 하드웨어 여유 미확정. diff는 추가로 정책 forward(<0.1 ms)뿐이라
  구조적 위험은 낮음.
- **C-6 (preview 공급 의존)**: E4a에서 horizon preview 제거 시 +41% — 하드웨어
  참조 생성기(scan_loop)가 preview를 동일 규약으로 공급해야 함. sim-to-real의
  `WallScanControlLoop` 코어 공유 설계가 이를 보장하는지 병합 시 확인.
- **C-7 (주장 범위)**: "zero-shot 충분"은 준정적 도메인 한정 주장으로 서술할 것.
  리뷰어의 "그럼 가변 가중치가 왜 필요한가"에 대한 답은 플랜트가 아니라 상황
  적응 (E4a·F7·E3)이라는 증거 세트로 준비되어 있음.
- **C-8 (미완 대조 실험)**: 보수 lr(2.9e-5) 대조, 원논문식 초기화 강건성(무작위
  가중치 30개 수렴) 대응 실험 — 여력 시 부록감.
- **C-9 (병합 리스크)**: sim-to-real의 `run_mpc_cell`→`WallScanControlLoop`
  리팩토링 병합 시 회귀 스모크 필수 (그쪽 sfix s4=96.7 재현 + 우리 E1 diff s0=13.3
  재현을 양방향 게이트로).
